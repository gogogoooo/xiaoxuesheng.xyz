实际 Wasm 测试覆盖 MP4 → FLV → MP4 往返，比较起始 MP4 与返回 MP4 的时长、音视频包数量；检查 FLV 文件头和 H.264/AAC 编码，并验证重新编码输出。浏览器已实际下载 FLV、重新选入并转回 MP4，另验证 FLV 重新编码成功。390px 视口下三个视频格式按钮无横向溢出。

## 使用

入口位于“小程序、Demo 与工具”页面，工具地址为 `/tools/media-converter/`。

选择本地文件，设置输出格式后点击“开始转换”。首次下载约 32 MB 的引擎程序，源文件及结果不会上传。转换完成后可以预览、下载；更换文件、修改设置、重新转换或离开页面会释放旧结果，请及时下载。

- 视频输入：FLV、MP4、MOV、MKV、WebM、AVI。
- 音频输入：MP3、WAV、M4A、AAC、FLAC、Ogg。
- 输出：MP4、WebM、MP3、WAV、AAC、FLAC。实际支持取决于源编码，并非任意编码均可转换。
- 自动模式优先保留兼容的编码；仅音频不兼容时只转音频。调整分辨率或选择重新编码时生成新视频。
- 默认只保留第一条真实视频和音频，不保留字幕；存在多轨道时提示。
- 每次一个文件，必须大于 0 且严格小于 1,000,000,000 字节。超过 300 MB 会提示内存要求；这不是成功处理 1 GB 的保证。
- 可取消任务，实际终止 Worker 后允许重新开始。没有断点续转。

建议使用新版桌面 Chrome / Edge，必须通过 HTTPS 或 localhost/127.0.0.1 打开。不能直接双击 HTML 后期待引擎正常运行。手机、其他浏览器和大体积转码需按实际环境验证。

## 开发与构建

在网站工作目录执行：

```powershell
pnpm install --frozen-lockfile
node scripts/prepare-media-engine.mjs
node scripts/preview-media-converter.mjs
```

本机预览：[打开格式工坊](http://127.0.0.1:3012/tools/media-converter/)。预览服务只服务本工具，页头回首页需完整网站开发服务才能验证。

```powershell
pnpm test:media
node --test tests/site-content.test.mjs tests/circuit.test.mjs
pnpm build
```

`pnpm build` 自动准备引擎，再构建静态站点。Cloudflare Pages 继续使用现有 Git 自动部署方式，构建命令 `pnpm build`，输出目录 `dist/client`。不要把本工具单独建成另一个 Pages 项目，也不要只上传工具目录覆盖整个网站。

## 模块与资源

| 文件 | 职责 |
| --- | --- |
| `public/tools/media-converter/app.js` | 页面交互、真实阶段、预览和下载 |
| `converter-controller.js` | 单任务、取消竞态、下载 URL 回收 |
| `conversion-policy.js` | 文件边界、编码兼容、音频保真、分辨率和体积预估 |
| `engine/core-loader.js` | 同源下载、分片与整体 SHA-256 校验 |
| `engine/ffmpeg-adapter.js` | WORKERFS、检测、执行、输出检查与 Worker 释放 |
| `engine/probe-result.js` | 固定版本 ffprobe 返回值兼容及媒体信息校验 |
| `engine/deadline.js` | Worker 初始化无响应时的 90 秒超时保护 |
| `scripts/prepare-media-engine.mjs` | 生成内容版本目录、清单、许可证及大小检查 |
| `scripts/licenses/` | 上游许可证原文 |

固定使用 `@ffmpeg/ffmpeg 0.12.15` 和单线程 `@ffmpeg/core 0.12.10`。不需要跨源隔离响应头或 SharedArrayBuffer。不要只升级一个包而跳过真实集成验证。

核心 Wasm 为 32,232,419 字节，构建时拆为 2 个不超过 16 MiB 的 `.bin`，避免 Pages 单文件 25 MiB 限制。`vendor/` 和 `engine-manifest.json` 为生成物，不提交 Git；构建不能跳过开发依赖安装。`public/_headers` 只为版本化资源加不可变缓存，清单不缓存。

输入通过 WORKERFS 只读挂载，避免先复制整个源文件。输出仍需占用 Wasm 内存和结果 Blob；输出读取前后均检查大小，WAV 会先估算体积。这些保护不能消除浏览器内存不足的可能。

固定核心的 ffprobe 成功后 `ret` 也可能为 `-1`。实现仅接受 0/-1 且必须有可解析的媒体流信息，空 JSON、损坏文件、其他错误返回码仍拒绝。真实 Wasm 测试覆盖这个兼容点。

## 已验证与边界

本地 Windows、Codex 内嵌 Chromium 环境：

- H.264/AAC FLV 快速转 MP4，中文下载名正常；实际下载的 MP4 可读取画面、分辨率和时长。
- MOV、MKV 快速转 MP4；WebM 转 MP4；H.264/MP3 FLV 仅重编码音频。
- MP4、WebM、MP3、WAV、AAC、FLAC 六种输出均经真实核心检测；浏览器 MP4、WebM 及音频预览正常。
- WAV 纯音频输入；损坏文件拒绝；无音轨视频提取音频有明确提示。
- 60 秒视频重编码过程中取消，然后快速转封装成功。
- 33,555,989 字节、15 分钟合成重复视频转封装成功。该样本用于基本体积验证，不代表复杂高分辨率视频性能。
- 转换期间浏览器网络记录仅有程序资源 GET 和本地 Blob 读取，没有媒体上传。
- 390px 手机视口无横向溢出；尚未验证手机真机内存与性能。
- 自动测试含转换策略、取消竞态、URL 回收、分片校验、加载超时、检测返回值兼容，以及真实 Wasm 六格式集成转换；另有站点和电路回归测试。

上线验证：Cloudflare Pages 预览部署和生产部署均成功；正式 `/apps` 入口及原生链接跳转正常，线上清单与本地 SHA-256 一致。正式 HTTPS 页已实际完成中文 H.264/AAC FLV 到 MP4 的转换，生成 51 KB 结果及下载按钮。

接近 1 GB、高分辨率长视频、多浏览器真机尚未实测。后续升级先验证本地和 Pages 预览域，再发布生产分支。
