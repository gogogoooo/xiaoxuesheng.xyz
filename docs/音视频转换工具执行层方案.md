# 音视频转换工具：浏览器执行层方案

日期：2026-10-27。状态：前端设计已获用户认可；本文为功能实现设计，尚未接入真实转换或发布。

## 1. 目标与约束

把现有 `/tools/media-converter/` 设计稿接成可以实际处理文件的工具。这里的“后台”是浏览器内运行的转换执行层：网站继续由 Cloudflare Pages 提供静态文件，视频处理消耗访问者电脑的 CPU 和内存。

- 不增加算力服务器，不提供媒体上传或服务端转码接口。
- 输入文件必须大于 0 字节且严格小于 1,000,000,000 字节；每个页面一次运行一个任务。
- 视频输出 MP4、WebM；音频输出 MP3、WAV、AAC、FLAC。
- 常见输入容器包括 FLV、MP4、MOV、MKV、WebM、AVI；音频输入包括 MP3、WAV、M4A、AAC、FLAC、Ogg。
- 容器扩展名只做初步筛选，是否能转换由实际流编码和固定版本的引擎能力决定。
- 优先服务桌面 Chrome / Edge；其他浏览器按实际验证结果标注支持程度。
- 小于 1GB 是文件选择上限，不是所有设备、编码和输出格式的成功保证。

## 2. 推荐结构

```mermaid
flowchart LR
  A[现有网页：选择文件与设置] --> B[任务控制器]
  B --> C[文件检测与转换计划]
  C --> D[本机 Web Worker]
  D --> E[FFmpeg.wasm：读文件与转换]
  E --> F[本机结果 Blob 与下载]
  D -->|阶段、进度、错误| B
  G[Cloudflare Pages：页面及引擎资源] -->|只下载程序资源| A
  G -->|只下载程序资源| D
```

输入视频沿本机 File → Worker 文件系统 → FFmpeg 的路径流转，不发送给 Cloudflare 或其他第三方。Web Worker 使用 FFmpeg 包自带的执行 Worker，不额外堆叠一层执行 Worker。界面主线程只负责交互、少量元数据和进度渲染。

### 模块职责

| 模块 | 职责 |
| --- | --- |
| `app.js` | 复用当前 DOM 交互，把选择和配置交给控制器，呈现真实状态 |
| `converter-controller.js` | 单任务状态、任务 ID、开始、取消、结果生命周期与清理 |
| `conversion-policy.js` | 文件限制、输出编码策略、参数白名单、预计输出大小检查 |
| `engine/core-loader.js` | 版本清单、核心资源分片下载、校验、Blob URL 与加载进度 |
| `engine/ffmpeg-adapter.js` | 初始化、挂载 File、ffprobe、执行参数数组、事件转换与资源释放 |
| 构建脚本 | 从固定版本 npm 包准备自托管资源，拆分 Wasm，生成清单并检查部署文件大小 |

公开入口保持 `/tools/media-converter/`。功能通过验证后，再接入网站 `/apps` 的小工具入口。

## 3. 引擎选择与核实结果

建议第一版固定使用：

- `@ffmpeg/ffmpeg@0.12.15`。
- `@ffmpeg/core@0.12.10`，使用单线程核心。
- 不使用 `latest`、版本范围或第三方网页动态注入脚本。

2026-10-27 已只读核对 npm 元数据和发行文件：

- 包装层包含 `ffprobe`、`mount`、`unmount` 等接口。
- 核心 JS 包含 `WORKERFS` 与 `ffprobe` 实现。
- 核心 Wasm 的 CDN 文件元数据显示为 **32,232,419 字节，约 30.74 MiB**。

这些检查证明发行包具备所需接口，不等于浏览器内的端到端运行验证。实施第一步仍需用实际文件跑通固定版本组合。

选择单线程是为了先控制内存和部署复杂度，也避免首版依赖 SharedArrayBuffer 所需的跨源隔离。暂不为全站增加 COOP / COEP 响应头。多线程作为后续独立优化，需单独验证性能收益、额外内存与嵌入兼容性。

## 4. 引擎资源如何放进现有 Pages

Cloudflare Pages 单个静态资源上限为 **25 MiB**。30.74 MiB 的原始 Wasm 不能直接作为一个资源发布；这个限制约束程序资源，不是本机选择的视频文件大小。

### 推荐：同站点分片加载

1. 构建时从锁定的 npm 包取出 ESM 包装层、Worker、核心 JS 和 Wasm。
2. 将 Wasm 拆成两个不超过 16 MiB 的二进制资源；以当前发行文件计算，分别是 16,777,216 和 15,455,203 字节。
3. 生成版本清单，包含包版本、每片文件名、字节数、SHA-256、拼接顺序和整体校验值。校验值必须从实际构建文件计算。
4. 浏览器从同域名获取分片，核对长度和哈希，按顺序组装为 `application/wasm` Blob，再把 Blob URL 交给引擎。
5. 构建产物不保留超限的原始 `.wasm`；发布前扫描所有静态资源，超限直接使构建失败。

这是待实施的加载适配方案，必须先验证固定版本的 `load({coreURL, wasmURL, classWorkerURL})` 和 Blob URL 的配合。

### 构建与缓存

- 将引擎准备脚本显式串入现有 `build` 命令，在 `vinext build` 之前运行，不依赖包管理器是否执行隐式 `prebuild`。
- 生成的 vendor 目录不手工编辑，加入忽略规则；Cloudflare 构建时根据锁文件生成。
- 保留包装层 ESM 文件之间的相对路径，确保 Worker 依赖同域可达。
- 版本和内容哈希进入核心资源路径，允许长缓存；稳定地址的版本清单应重新验证缓存。
- 首次使用只下载程序资源，之后可利用浏览器缓存；不承诺离线可用。
- 保留第三方许可证、版权和对应源代码获取说明。

第一版无需新增 R2。若分片适配实测存在问题，可改用固定版本、允许 CORS 的 CDN 加载核心，但需明确外部资源依赖，不能悄悄添加服务器上传回退。

## 5. 文件读取、识别与内存

### 输入优先使用 WORKERFS

使用 `ffmpeg.mount(WORKERFS, {blobs: [{name, data: file}]}, mountPoint)`，将本地 File / Blob 只读映射到 Worker。内部名称和路径由任务 ID 生成，原始中文文件名仅用于界面和下载名称。

这样可以减少 `file.arrayBuffer()` → 主线程缓冲区 → `writeFile()` → 内存文件系统这类整文件复制。不能把它称为“整个转换零拷贝”：解码、编码和输出仍然消耗内存。

首版要求固定核心的 WORKERFS 挂载试验通过。若该能力在目标环境不可用，应报出兼容性问题；不对接近 1GB 的文件偷偷切回多份整文件复制。

### 元数据检测

选择文件后可以继续利用现有浏览器元数据预读作为辅助显示。用户开始处理时，再用 ffprobe 获取实际容器、主视频流、主音频流、编码、分辨率、帧率、时长、采样率和声道数。

- 浏览器不能播放 FLV，不代表 FFmpeg 不能处理，不能用 `<video>` 预读失败作为最终拒绝理由。
- 视频输出需要真实视频流，排除音频封面图片流；提取音频需要音频流。
- 第一版只处理一个主视频流和一个主音频流。多音轨或字幕文件必须在界面说明保留范围，不能直接 `-map 0` 把所有轨道都塞进结果。
- 元数据缺失时不猜测编码；允许可执行的保守方案或给出明确错误。

### 大文件边界

- 300 MB 以上显示较大文件提示，建议电脑端处理，不把这条提示当能力检测。
- 不使用浏览器内存估计接口作为成功承诺，也不按“文件大小乘固定倍数”宣称精确内存需求。
- 输出也占用内存。特别是长音频转 WAV，输出可能比源文件大很多；检测到可估算的过大输出，应在执行前阻止并建议压缩格式。
- WAV 预测按确定的目标时长、采样率、声道数和 PCM 位深计算；默认控制预计输出小于 1GB。参数无法可靠估算时如实提示，不能展示虚假的预计体积。
- 首版输出仍采用内存文件系统和 Blob 下载。WORKERFS 优化输入，并不能解决所有大输出内存问题。
- 分别实测小文件、300MB、700MB、接近 1GB 的转封装；转码还需区分时长、编码与分辨率。页面被浏览器回收或进程被终止时，不能承诺总能捕获并优雅报错。

## 6. 自动选择转换方式

用户设置为“自动”时，根据实际编码制定计划；“重新编码”则明确执行重编码。画质配置只在重新编码时生效，修改分辨率会强制重编码。

| 输出 | 优先处理 | 需要重编码时 |
| --- | --- | --- |
| MP4 | 经检测兼容的 8-bit YUV 4:2:0 H.264 视频及 AAC 音频优先直接复制；音频不兼容时可只重编码音频 | H.264 视频 + AAC 音频；允许无音轨视频 |
| WebM | 兼容的 VP8 / VP9 与 Opus / Vorbis 流优先复制 | 第一版以 VP8 + Opus 为基础，避免默认使用更耗时的 VP9 编码 |
| MP3 | 兼容 MP3 音频优先复制 / 提取 | MP3 编码，按所选音频质量设置码率 |
| WAV | 输出 PCM，不采用有损码率设置 | 确定 PCM 位深、采样率和声道数后预估体积 |
| AAC | 编码兼容时复制，按目标 ADTS 容器调整封装 | AAC 编码，输出 `.aac` |
| FLAC | 兼容 FLAC 时复制或重封装 | FLAC 编码；不会恢复源文件已损失的音质 |

“兼容”仍需以固定版本的容器、编码及测试样本确认，不能只用上表当完整兼容性清单。

参数策略：

- 参数使用数组传给 FFmpeg，不经过 shell，也不接受用户提供任意命令。
- 显式映射选中的流；文件路径和目标后缀由程序生成。
- H.264 编码优先采用面向浏览器 CPU 的速度预设及 `yuv420p`。质量预设初始映射为 CRF 20 / 23 / 28，实际性能和画质测试后调整。
- 选择 1080p / 720p 时不放大小分辨率视频，保持比例并处理横竖方向；必要时规范为编码器要求的偶数尺寸。
- WAV / FLAC 优先保留源采样率、声道和引擎支持的位深；因目标编码限制必须改变声道等信息时明确显示，不把这类处理宣传为完全无损。
- MP4 完成时处理 `faststart`；文件整理阶段结束前不显示转换成功。
- 无损转封装失败时仅允许有边界的重试，不把损坏、取消、内存不足等错误都归结为编码不兼容。自动模式允许选择性转码时，界面应显示实际采用的方式。
- 不用限制文件字节数的参数生成截断文件后宣称成功。

## 7. 任务状态与接口

### 公开接口草案

```ts
type OutputFormat = 'mp4' | 'webm' | 'mp3' | 'wav' | 'aac' | 'flac';

type ConversionRequest = {
  file: File;
  format: OutputFormat;
  mode: 'auto' | 'encode';
  quality: 'balanced' | 'high' | 'small';
  resolution: 'original' | '1080' | '720';
};

type ConversionResult = {
  taskId: string;
  blob: Blob;
  filename: string;
  mime: string;
  size: number;
  method: 'copy' | 'audio-encode' | 'encode';
};

type Stage = 'loading-engine' | 'probing' | 'planning' | 'converting' | 'finalizing';

type ConversionEvent =
  | {taskId: string; type: 'stage'; stage: Stage}
  | {taskId: string; type: 'progress'; stage: Stage; ratio: number | null; processedSeconds?: number}
  | {taskId: string; type: 'warning'; code: string; message: string};

// start(request, onEvent): Promise<ConversionResult>
// cancel(): void
// dispose(): void
```

这些是浏览器模块接口，不是要新增的网络 API。原生 File 直接进入本机适配层，不编码成 Base64，也不放进 JSON 请求。

### 状态流转

```text
待选择 → 已选择 → 加载引擎 → 检测文件 → 规划方式 → 转换中 → 整理结果 → 可下载
                    └──────── 任一运行阶段 ────────→ 取消 / 失败
```

- 每个任务有独立 taskId；新任务、取消后延迟到达的旧事件不得覆盖当前界面。
- 处理期间禁止重复开始或悄悄替换输入文件，允许明确取消。
- 同一页面最多一个有效 Worker 任务，不建立并发转换队列。
- 替换、清空或开始新任务时回收上一结果的 Blob URL。

## 8. 真实进度、取消与结果

### 进度

引擎加载、媒体处理、结果整理分阶段显示。引擎分片下载可以按实际读取字节数显示进度。转换阶段消费 FFmpeg 的实际进度事件，并结合有效时长判断是否可显示百分比；没有可靠时长就显示“正在处理”，不模拟计时增长。

执行返回成功码不直接等于用户可以下载。必须等待输出存在、非空、媒体检测通过并建立下载 Blob 后，才进入“可下载”。处理中的百分比不得提前宣称整个任务完成；最后应单独展示整理结果阶段。第一版不提供未经测算的剩余时间。

### 取消

真正取消调用 `ffmpeg.terminate()`，终止工作线程，再按当前 taskId 标记为取消。只停止 Promise 等待或使用 AbortSignal 不作为“已停止转码”的保证。

引擎终止后需要重新加载才能运行下一任务。已缓存的程序资源可以复用；取消产生的拒绝和旧事件不能变成新的错误弹窗。

### 下载和释放

- 输出先检测并生成 Blob，只保留一次结果所需的数据引用。
- 下载名采用安全的原文件主名加 `_converted` 和目标扩展名，中文名称通过 DOM 文本和下载属性安全呈现。
- 下载采用 Blob URL；不在点击瞬间立即 revoke，避免浏览器尚未接管下载。
- 在重新转换、清空、替换结果或离开页面时 revoke；运行完成和失败后均释放 Worker、文件系统和监听器。
- Worker 已终止时，不再调用其文件系统清理 API；活跃引擎走正常卸载 / 删除，再 terminate。
- 成功后可保留 Blob 下载结果，但不把源视频、结果视频或完整媒体日志存入 localStorage、IndexedDB 或服务器。

## 9. 错误提示

| 情况 | 页面行为 |
| --- | --- |
| 空文件、达到 1GB、类型初筛不通过 | 执行前在源文件区提示，可重新选择 |
| 下载核心失败或校验不一致 | 显示引擎加载失败，允许重新加载，不开始转换 |
| 文件损坏或无法检测 | 保留源文件名称，说明无法识别，不重复盲试 |
| 请求的输出编码器不可用 | 隐藏或禁用不支持格式，说明当前引擎支持范围 |
| 提取音频但文件没有音轨 | 说明无可提取音频，不生成空结果 |
| 预计 WAV 等输出过大 | 在执行前建议压缩输出格式 |
| 运行时内存不足或 Worker 异常 | 清理当前任务，建议更小文件 / 较低分辨率 / 电脑端处理 |
| 用户取消 | 显示“已取消”，保留重新开始的选择，不显示错误 |
| 整理输出失败 | 显示失败，不开放损坏或空文件下载 |

调试日志只保存在当前会话的有限长度缓冲区，默认不上传。初版不开放远程视频 URL、直播流、批量处理、复杂剪辑或多轨道编辑。

## 11. 实施顺序与验收

### 第一步：核心可行性验证

固定版本依赖 → 构建分片 → 浏览器加载 → WORKERFS 挂载 → ffprobe → 一份 H.264/AAC FLV 转封装为 MP4 → 真实下载播放 → 取消后重新运行。

这一步验证后再扩展格式，防止先铺开功能后才发现核心加载或内存路径不适用。

### 第二步：转换策略与错误闭环

完成 MP4、WebM 和四种音频输出；补齐只转音频、无音轨、多轨道说明、损坏文件、空文件、尺寸上限、输出体积预估、中文文件名、重复点击与取消竞态。

### 第三步：接入已批准界面

替换禁用的开始按钮，展示实际处理方式和阶段；绑定质量 / 分辨率，接入真实结果、取消、重新开始、资源回收。

### 第四步：发布前验证

- 转换策略做有意义的单元测试；引擎用实际媒体文件做集成验证，不能用成功 Promise 的 mock 代替。
- 首批覆盖：H.264/AAC FLV、MOV、MKV、WebM、无音轨视频、仅音频、损坏文件，以及 MP3/WAV/AAC/FLAC 输出。
- 核实输出文件可播放、时长和流信息符合预期，不能只看扩展名。
- 测试取消后不再消耗该 Worker 的 CPU，下一次任务可以恢复；连续处理多个小文件没有遗留 Worker 和 Blob URL。
- 验证大文件的实测边界，记录设备、浏览器、输入编码、时长、大小、模式和结果，不给无法复现的速度承诺。
- 检查网络请求仅涉及页面和引擎资源，没有源文件或输出文件上传。
- 检查所有发布资产小于 25 MiB、版本清单正确、Pages 预览域可加载核心。
- 网站静态构建通过，再检查线上 HTTPS 下的下载与浏览器兼容性。
