# 汇报材料子目录与密码门禁设计

## 目标

在“网页 / 网站 / 汇报材料”栏目下增加独立的“汇报材料”目录，展示 2026 年国庆基础采集研发部门汇报稿，并通过普通密码门禁避免普通访客误入。

## 范围

- 新增汇报材料目录路由：`/works/reports`。
- 新增汇报材料详情路由：`/works/reports/2026-national-day-collection`。
- 在作品页增加“汇报材料”入口卡片。
- 将指定 Markdown 文档转成适合网页阅读的静态内容。
- 搭配文档引用的四张 PNG 配图。
- 默认访问密码为 `god1988`。
- 在当前浏览器会话中保存解锁状态，并提供重新锁定操作。

## 架构

站点继续使用 Next/Vinext 静态导出，所有路由在构建阶段生成。密码门禁作为客户端交互层存在：目录和详情页在未解锁时显示密码表单，解锁后才显示材料导航和正文。密码以摘要形式参与校验，避免在界面和普通配置中直接显示；该门禁只用于防止普通访客误入，不承诺抵御源码查看或专业抓取。

汇报稿正文以站点内的静态结构化内容呈现，不依赖运行时 API。四张配图放在 `public/reports/2026-national-day/` 下并使用站内绝对路径引用。

## 交互

1. 访客进入 `/works/reports`，看到标题、说明和密码输入框。
2. 输入正确密码后，使用 `sessionStorage` 保存本次浏览器会话的解锁标记，并显示材料卡片。
3. 输入错误时显示中文错误提示，不暴露正确密码。
4. 点击材料卡片进入详情页；详情页也独立检查解锁状态，直接访问详情 URL 时不能绕过门禁界面。
5. 点击“重新锁定”清除会话标记并返回门禁状态。

## 验收标准

- 作品页存在“汇报材料”入口且链接可用。
- 未解锁时 `/works/reports` 不显示正文内容。

- `node tests/site-content.test.mjs`、`node tests/circuit.test.mjs` 和 `pnpm build` 全部通过。
