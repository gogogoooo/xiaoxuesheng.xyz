# 花园防线：紧凑界面与可调玩法设计

## 目标与范围

在现有独立离线游戏 `public/games/garden-defense/` 内完成三项扩展：缩小视觉占用、增加三组局内设置、新增三种原创植物。保留 5×9 草坪、三波进攻、现有四种植物、暂停/重开/触屏操作。网站其他栏目及流沙游戏不改动；先本地验证，不自动发布。

## 界面

- 桌面版将页面最大宽度由 1510px 收至 1240px，草坪显示宽度上限 1040px、平板目标为容器宽度的约 92%，手机最小滚动宽度由 730px 降至 650px；同时压缩页头、介绍区、游戏框上下留白。Canvas 的逻辑尺寸仍为 1000×560；通过 CSS 适应容器，不用 `transform: scale()`，保持触点换算可靠。
- 植物卡片改为单行横向可滚动的紧凑选择栏，包含七种植物和铲子。卡片保留图形、名称、简短作用与阳光价格；被选中状态明显。平板和手机可横向滚动，不把文字挤到无法阅读。
- HUD 增加可展开的“游戏设置”。三组按钮分别为“每朵阳光：25 / 50 / 100 / 200 / 500”、“豆豆射手连发：1 / 2 / 4 / 8 / 16”和“冰冻／双向射手攻击间隔：0.25 / 0.5 / 1 / 1.5 / 2 秒”。第三组由两种射手共用，不分别设置；当前档位明确标记；触屏目标不小于现有植物卡片的主要点击区。
- 游戏主画面与设置不互相遮挡；设置展开后可滚动。保留暂停、重开、胜负覆盖层和返回作品集入口。

## 玩法规则

- 默认每朵阳光 25、豆豆射手每轮 1 发、冰冻／双向射手攻击间隔 1.5 秒。选择新档位后立即影响此局：场上尚未领取的阳光和之后产生的阳光均采用所选值，已经入账的阳光不追溯；已种豆豆射手的后续攻击也采用新连发数；已种冰冻与双向射手从下一轮攻击起采用新间隔。重开保留这三个所选档位；刷新页面恢复默认，不使用本地存储。
- 天降阳光与向日花产生的阳光均遵循同一档位。游戏开始阳光仍为 150、植物消耗与冷却保持原值。高档位属自由玩法，不额外按难度缩放敌人。
- 豆豆射手每轮生成 1、2、4、8 或 16 发独立弹丸；弹丸以起点微小水平间隔形成可见队列，每发沿用当前的 24 点伤害。连发仅作用于原有豆豆射手，不改变冰冻和双向射手。
- 冰冻射手：费用 125、冷却 7 秒、生命 140、默认射击间隔 1.5 秒；同一行向右射击，命中造成 16 点伤害，并让目标以原速的 50% 移动 3 秒。重复命中只刷新剩余时间，不叠加减速倍数。
- 地刺：费用 75、冷却 8 秒、生命 180；每秒对处在本格内的敌人造成 45 点伤害。可被敌人攻击和铲除，不越行攻击。
- 双向射手：费用 175、冷却 9 秒、生命 140、默认射击间隔 1.5 秒；当同一行左右任一侧有敌人时，分别向对应方向发射 24 点伤害弹丸。向左弹丸在离开草坪后清理，避免无限积累。
- 新植物沿用现有单格占用、费用、冷却、铲除与胜负规则。三波数量和敌人属性暂不改动。

## 代码边界

- `rules.js`：保留纯规则、无 DOM 依赖；新增设置状态、七种植物配置、子弹方向/减速、地刺伤害。新增和既有植物使用相同 `plant`、`tick` 接口。
- `game.js`：设置按钮事件、选中/禁用状态、七种植物和多发弹丸绘制；继续使用 Canvas 坐标与 `getBoundingClientRect()` 转换触点。
- `index.html`、`style.css`：紧凑布局、可横向滚动卡片和设置面板；脚本仍为相对路径，双击 HTML 可离线运行，不增加依赖或外部素材。
- 测试：规则测试先失败后实现，覆盖三组设置的即时效果、重开保留、连发数量、两种射手共用攻击间隔、三种植物功能及边界；浏览器本地检查桌面、平板和手机布局与触屏按钮。全站测试与静态构建须通过。

## 验收

桌面/Android 平板上的游戏画面与卡片明显比现版紧凑，草坪不变形；三组设置可在游戏中切换并正确影响规则；三种新植物能种植、攻击或阻挡，图形和说明容易区分；原有四种植物及站点其他页面维持正常。上线需另行确认。
