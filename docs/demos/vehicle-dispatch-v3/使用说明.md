# 车辆调度 Demo V3.0 使用说明

## 一、版本定位

本版本是面向需求沟通的纯离线 HTML 演示程序，严格按手机微信小程序界面设计。它与原微信小程序 V2.0 代码完全独立，不连接云数据库，不上传任何信息。

- 双击 `index.html` 即可打开。
- 建议使用 Chrome、Edge 或微信开发者工具内置浏览器。
- 演示期间的数据只存在于当前页面内存中。
- 刷新、关闭后再次打开，自动恢复初始演示数据。
- “我的 → 恢复初始演示数据”可在不关闭页面的情况下立即复位。

## 三、最小权限说明

| 当前身份 | 可见业务 |
|---|---|
| 普通用户 | 用车申请、我的用车、本人加油登记 |
| 部门负责人 | 本部门用车审批 |
| 车管中心主任 | 用车、加油、维修、车辆档案和业务导出 |
| 车辆中心处长 | 主任全部权限及处级审批 |
| 司机班 | 派车及归还确认 |
| 修理工 | 报修和维修验收 |
| 修理厂 | 本厂报价和维修完工 |
| 系统管理员 | 人员权限、部门负责人绑定、数据导入导出、日志、设置和全量审计 |

系统会同时控制首页统计、菜单入口和页面访问。没有权限的身份即使尝试直接打开页面，也会返回业务中心。

### 部门范围规则

- 每个部门固定绑定一名部门负责人，由系统管理员在“业务中心 → 系统管理 → 部门管理”中维护。
- 部门负责人只会看到、也只能审批其绑定部门的用车申请；A 部门负责人不能查看或处理 B 部门用车单。
- 候选负责人仅限本部门在职人员；设置后自动具备“部门负责人”角色。
- 更换负责人不会修改已产生的申请、审批和审计记录。
- 系统管理员可新增部门；新增后先显示“待绑定负责人”。
- 删除部门采用安全删除：存在在职人员或任一历史用车单时不可删除，须先调整人员归属或保留该历史部门。

## 四、建议演示顺序

1. 使用 `wangmin` 登录，在“我的”中切换身份，说明一个账号可具有多个角色，不需要退出重登。
2. 普通用户提交用车申请；切换部门负责人、主任/车辆中心处长、司机班依次处理；再切回普通用户领车、上传前后照片并申请归还；最后由司机班确认收车。
3. 普通用户进入加油管理，登记本人当天或前一天使用过的车辆；主任可补登历史记录并导出对账表。
4. 修理工提交报修；主任分派一家修理厂；修理厂报价；主任或车辆中心处长审批；修理厂完工；修理工验收。
5. 打开车辆详情，展示同一车辆的用车、加油和维修全周期台账。
6. 切换系统管理员，进入“部门管理”展示新增部门、固定负责人绑定与安全删除提示，再展示人员权限、车辆导入预检、业务报表和操作日志。

用车单详情中，“用车流程”展示按用车类型生成的标准节点及当前进度；“操作记录”单独展示实际处理人、处理时间、意见和自动审批记录。

维修单详情同样拆分为“维修流程”和“操作记录”。维修流程按报价与最终金额是否超过 5000 元，动态显示车辆中心处长审核、最终金额复核等必要节点。

## 五、演示边界

- 照片按钮使用演示占位数据，不读取或保存真实照片。
- CSV 导出由浏览器在本机即时生成。
- 不包含真实微信授权、云数据库、短信、微信服务通知、GPS 或外部加油站系统对接。
- 正式开发时，权限校验、文件存储、审计、加密、备份和接口鉴权应在服务端实现。
